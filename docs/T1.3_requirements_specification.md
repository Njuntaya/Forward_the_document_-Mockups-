# Requirements Specification

โครงการ: เว็บแอปพลิเคชันคำร้องขอเอกสารสำหรับนักศึกษา
อ้างอิง: Task 2.1

## 1. Functional Requirements (FR)

| Requirement ID | รายละเอียด | ผู้เกี่ยวข้อง (Actor) |
|---|---|---|
| FR-01 | นักศึกษาสามารถเข้าสู่ระบบและยื่นคำร้องขอเอกสารได้ | นักศึกษา |
| FR-02 | ระบบสามารถแสดงประเภทเอกสารที่ขอได้ (เช่น ใบรับรอง, ใบแสดงผลการศึกษา) | นักศึกษา |
| FR-03 | เจ้าหน้าที่/ผู้อนุมัติสามารถตรวจสอบและอนุมัติ/ปฏิเสธคำร้องได้ | เจ้าหน้าที่ |
| FR-04 | ระบบสามารถออกเอกสาร PDF พร้อม QR Code เมื่อคำร้องได้รับการอนุมัติ | ระบบ |
| FR-05 | QR Code บนเอกสารสามารถใช้ตรวจสอบความถูกต้อง (verify) ของเอกสารได้ | ผู้ตรวจสอบเอกสาร |
| FR-06 | ระบบสามารถแสดงสถานะคำร้องแบบ real-time ให้นักศึกษาติดตามได้ | นักศึกษา |
| FR-07 | ระบบสามารถบันทึกประวัติการยื่นคำร้องทั้งหมดของนักศึกษาได้ | นักศึกษา, เจ้าหน้าที่ |


## 2. Non-Functional Requirements (NFR)

| Requirement ID | หมวดหมู่ | รายละเอียด |
|---|---|---|
| NFR-01 | Performance | ระบบต้องประมวลผลและแสดงผลหน้าเว็บภายใน 3 วินาที ภายใต้การใช้งานปกติ |
| NFR-02 | Security | ข้อมูลผู้ใช้และเอกสารต้องเข้ารหัสและจำกัดสิทธิ์การเข้าถึงตามบทบาท (Role-based Access Control) |
| NFR-03 | Availability | ระบบต้องพร้อมใช้งานไม่น้อยกว่า 99% ในช่วงเวลาราชการ |
| NFR-04 | Usability | หน้าจอใช้งานต้องเข้าใจง่าย รองรับการใช้งานบนมือถือ (Responsive) |
| NFR-05 | Compatibility | ระบบต้องทำงานได้บนเบราว์เซอร์หลัก (Chrome, Firefox, Edge, Safari) |
| NFR-06 | Data Integrity | เอกสาร PDF ที่ออกแล้วต้องไม่สามารถแก้ไขเนื้อหาได้ และ QR Code ต้องยืนยันได้ว่าไม่ถูกปลอมแปลง |
