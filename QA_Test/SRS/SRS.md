# Software Requirements Specification (SRS)
## ระบบยื่นคำร้องออนไลน์สำหรับนักศึกษา (ENGSE205)

**เวอร์ชันเอกสาร:** 1.0
**อ้างอิงจาก:** Sprint Backlog ENGSE205 (Google Sheets)

---

## 1. บทนำ (Introduction)

### 1.1 วัตถุประสงค์ (Purpose)
เอกสารฉบับนี้จัดทำขึ้นเพื่อระบุความต้องการ (Requirements) ของระบบยื่นคำร้องออนไลน์
สำหรับนักศึกษาและเจ้าหน้าที่ โดยรวบรวมจาก Requirement ของลูกค้า (Customer) และ
Test Case ที่กำหนดไว้ใน Sprint Backlog เพื่อใช้เป็นแนวทางในการออกแบบ พัฒนา
และทดสอบระบบ

### 1.2 ขอบเขตของระบบ (Scope)
ระบบเป็นเว็บแอปพลิเคชันที่รองรับผู้ใช้งาน 2 กลุ่มหลัก คือ **นักศึกษา** (ผู้ยื่นคำร้อง)
และ **เจ้าหน้าที่** (ผู้ดำเนินการคำร้อง) โดยระบบต้องรองรับการใช้งานบนอุปกรณ์
มือถือ แท็บเล็ต และคอมพิวเตอร์ตั้งโต๊ะ

### 1.3 กลุ่มผู้ใช้งาน (User Classes)
| กลุ่มผู้ใช้ | บทบาท |
|---|---|
| นักศึกษา (Student) | สมัครบัญชี, เข้าสู่ระบบ, ยื่นคำร้อง, ติดตามสถานะคำร้อง, ติดต่อเจ้าหน้าที่ |
| เจ้าหน้าที่ (Staff) | เข้าสู่ระบบ, ดูรายการคำร้อง, เปลี่ยนสถานะ, แจ้งแก้ไขรายละเอียดคำร้อง |

---

## 2. ภาพรวมของระบบ (Overall Description)

ระบบแบ่งออกเป็น 5 กลุ่มฟังก์ชันหลัก ได้แก่
1. การยืนยันตัวตนและบัญชีผู้ใช้ (Authentication & Account Management)
2. หน้าหลักและการติดตามคำร้อง (Dashboard & Request Tracking)
3. รูปแบบและการแสดงผล (UI/UX)
4. การติดต่อสื่อสารและแจ้งเตือน (Communication & Notification)
5. ฝั่งเจ้าหน้าที่ (Staff/Admin Panel)

---

## 3. ความต้องการด้านฟังก์ชัน (Functional Requirements)

### 3.1 การยืนยันตัวตนและบัญชีผู้ใช้ (Authentication & Account Management)

| ID | Requirement | Test Case ที่เกี่ยวข้อง |
|---|---|---|
| FR-01 | ช่องเข้าสู่ระบบ (Login) ต้องใช้รหัสนักศึกษาในการล็อกอิน | เมื่อสร้างบัญชี (Create Account) ต้องบันทึกข้อมูลและสามารถเข้าสู่ระบบได้จริง |
| FR-02 | หน้า Login ต้องแยกสำหรับ "เจ้าหน้าที่" และ "นักศึกษา" | หน้า Login ต้องมีทั้งฝั่งเจ้าหน้าที่และนักศึกษา |
| FR-03 | มีปุ่มสมัครบัญชี (Register) | เมื่อสมัครบัญชีสำเร็จ ต้องสามารถเข้าสู่ระบบได้ทันที |
| FR-04 | มีปุ่มกู้คืนรหัสผ่านกรณีลืมรหัส | เมื่อกด "ลืมรหัสผ่าน" ระบบต้องส่งรหัส/ลิงก์ตั้งรหัสใหม่ผ่าน SMS หรืออีเมล พร้อม Key สำหรับ Reset รหัสผ่าน |
| FR-05 | สามารถแก้ไขข้อมูลบัญชีได้ เช่น ชื่อ, อายุ, รหัสผ่าน | แก้ไขรายละเอียดบัญชีได้สำเร็จและข้อมูลถูกบันทึก |
| FR-06 | สามารถลบบัญชีผู้ใช้ (Delete Account) ได้ | เมื่อต้องการลบบัญชี ต้องให้ผู้ใช้พิมพ์ยืนยันคำว่า "delete" ก่อนกดปุ่มยืนยันลบข้อมูล |
| FR-07 | มีระบบป้องกันการกดลบข้อมูลโดยไม่ตั้งใจ | ต้องมี Pop-up ยืนยันก่อนการลบข้อมูลทุกครั้ง |
| FR-08 | มีการป้องกันการใส่อีเมลไม่ถูกรูปแบบ | ระบบต้องป้องกันการกรอกอักขระพิเศษที่ทำให้ระบบผิดพลาด |
| FR-09 | ผู้ใช้แต่ละคนต้องมี ID เฉพาะตัวที่ชัดเจน | ตรวจสอบว่า ID ผู้ใช้ไม่ซ้ำกันในระบบ |
| FR-10 | ป้องกันข้อผิดพลาดจากการสร้างบัญชีพร้อมกันหลายคน (Concurrency) | ทดสอบการสมัครบัญชีพร้อมกันหลายคนต้องไม่เกิด Bug ข้อมูลซ้ำ/ชนกัน |

### 3.2 หน้าหลักและการติดตามคำร้อง (Dashboard & Request Tracking)

| ID | Requirement | Test Case ที่เกี่ยวข้อง |
|---|---|---|
| FR-11 | หน้าหลักต้องแสดงคำร้องที่นักศึกษาเคยยื่นไปแล้ว | หน้าแรกต้องแสดงรายการคำร้องที่ยื่นไป พร้อมปุ่มดำเนินรายการที่ Taskbar ด้านซ้าย |
| FR-12 | สามารถกดดูรายละเอียดสิ่งที่ต้องแก้ไขของแต่ละคำร้องได้ | ตรวจสอบว่าเปิดหน้ารายละเอียดคำร้องได้ถูกต้องตรงกับคำร้องที่เลือก |
| FR-13 | มีสถานะแสดงความคืบหน้าแต่ละคำร้อง (In Progress, Pending, Done, Fix) พร้อมสีกำกับ | มีสีบ่งบอกสถานะที่แตกต่างกันชัดเจนตามแต่ละสถานะ |
| FR-14 | มีสถานะแสดงช่องทางดำเนินการ (Online/Onsite) พร้อมสีกำกับ | มีสีแสดงสถานะ Online/Onsite แยกจากกันชัดเจน |
| FR-15 | แจ้งเตือนทุกครั้งที่เจ้าหน้าที่เปลี่ยนสถานะคำร้อง พร้อมระบุวันครบกำหนดดำเนินการและช่องทาง (Online/Onsite) | มีการแจ้งวันเวลาที่ต้องดำเนินการอย่างชัดเจนทุกครั้งที่มีการเปลี่ยนสถานะ |

### 3.3 รูปแบบและการแสดงผล (UI/UX)

| ID | Requirement | Test Case ที่เกี่ยวข้อง |
|---|---|---|
| FR-16 | สามารถเปลี่ยนธีมสีได้ (Dark Mode / Light Mode) | ตรวจสอบว่าสลับธีมมืด-สว่างได้ถูกต้องในทุกหน้า |
| FR-17 | สามารถปรับขนาดตัวอักษรได้ | ตรวจสอบว่าปรับขนาดตัวอักษรแล้ว Layout ไม่พัง |
| FR-18 | รองรับการแสดงผลบนมือถือ แท็บเล็ต และคอมพิวเตอร์ (Responsive) | เมื่อใช้งานบนมือถือ/แท็บเล็ต ต้องไม่มี Side Scrolling Bar |
| FR-19 | Layout ต้องดูง่าย มีสีบ่งบอกความหมายชัดเจน (เช่น แดง = อันตราย/ลบ, เขียว = ปลอดภัย/ส่ง) | มีสีบ่งบอกชัดเจน: ปุ่มลบ = สีแดง, ปุ่มส่ง/ยืนยัน = สีเขียว |
| FR-20 | ฟอนต์หัวข้อ (Heading) ต้องมีขนาดใหญ่กว่าข้อความทั่วไป | ตรวจสอบขนาดฟอนต์หัวข้อเทียบกับเนื้อหาในทุกหน้า |
| FR-21 | มีแอนิเมชันเมื่อเลื่อนเมาส์ไปวางบนปุ่ม/รายการที่คลิกได้ (Hover Effect เช่น ขยาย หรือขึ้นเงา) | ตรวจสอบว่า Hover แล้วมี Feedback ทางภาพชัดเจนว่ากดได้ |
| FR-22 | ระหว่างหน้าเว็บกำลังโหลดข้อมูล ต้องมีการแสดงสถานะ (Loading Indicator) ให้ผู้ใช้ทราบ | เมื่อหน้าเว็บโหลด ต้องขึ้นสถานะ Loading ตามจริง |
| FR-23 | มีคู่มือ/แนวทางการใช้งานเว็บไซต์เบื้องต้น (Guide) | ตรวจสอบว่าผู้ใช้ใหม่สามารถเข้าถึงคู่มือการใช้งานได้ |
| FR-24 | เมื่อกดรีเซตหน้าเว็บ ข้อมูลที่ผู้ใช้กำลังกรอกอยู่ต้องไม่หายไปโดยไม่ตั้งใจ | ทดสอบการรีเซตหน้าเว็บระหว่างกรอกฟอร์ม ข้อมูลต้องไม่สูญหาย |

### 3.4 การติดต่อสื่อสารและแจ้งเตือน (Communication & Notification)

| ID | Requirement | Test Case ที่เกี่ยวข้อง |
|---|---|---|
| FR-25 | มีช่องทางติดต่อเจ้าหน้าที่โดยตรงในระบบ | เมื่อกดติดต่อเจ้าหน้าที่ ต้องมี Chatbot แจ้งสถานะคิวให้ผู้ใช้ทราบก่อนหากมีคิวจำนวนมาก |
| FR-26 | มีฟอร์มแจ้งปัญหาเว็บไซต์ (Bug Report) หรือข้อเสนอแนะการพัฒนาเว็บไซต์ | ตรวจสอบว่าข้อมูลที่แจ้งเข้าระบบและเจ้าหน้าที่สามารถดูได้ |
| FR-27 | มีเอกสารแจ้งนโยบายความเป็นส่วนตัว (Privacy Notice) เมื่อมีการเก็บข้อมูลส่วนบุคคล | ตรวจสอบว่าผู้ใช้ต้องรับทราบ/ยอมรับนโยบายก่อนใช้งาน |
| FR-28 | เมื่อดำเนินการไม่สำเร็จหรือเกิดข้อผิดพลาดร้ายแรง (Worst Case) ต้องมี Pop-up แจ้งเตือนพร้อมรหัสอ้างอิง (Error Code) | ทดสอบกรณี Error ต้องขึ้น Pop-up แจ้งเตือนพร้อมรหัสอ้างอิงทุกครั้ง |

### 3.5 ฝั่งเจ้าหน้าที่ (Staff / Admin Panel)

| ID | Requirement | Test Case ที่เกี่ยวข้อง |
|---|---|---|
| FR-29 | เจ้าหน้าที่สามารถดูรายการคำร้องทั้งหมดที่นักศึกษายื่นเข้ามาได้ | ตรวจสอบว่าเจ้าหน้าที่เห็นคำร้องครบถ้วนตรงกับที่นักศึกษายื่น |
| FR-30 | เจ้าหน้าที่สามารถระบุ/แจ้งรายละเอียดที่ต้องแก้ไขในช่องรายละเอียดของคำร้องได้ | ตรวจสอบว่าข้อความที่เจ้าหน้าที่กรอกแสดงผลถูกต้องฝั่งนักศึกษา |

## 4. ความต้องการที่ไม่ใช่ฟังก์ชัน (Non-Functional Requirements)

| ID | Requirement | Test Case ที่เกี่ยวข้อง |
|---|---|---|
| NFR-01 | **ประสิทธิภาพ (Performance):** ระบบต้องส่งและรับข้อมูลได้รวดเร็วและเสถียร | ทดสอบความเร็วในการส่งข้อมูลของฟอร์ม/คำร้องต่าง ๆ |
| NFR-02 | **ความปลอดภัย (Security):** ป้องกันข้อมูลผู้ใช้จากการกรอกอักขระอันตราย และป้องกันบัญชีซ้ำซ้อน | ตามที่ระบุใน FR-08 และ FR-10 |
| NFR-03 | **การใช้งานง่าย (Usability):** รองรับหลายอุปกรณ์ ปรับแต่งการแสดงผลได้ (ธีม/ขนาดตัวอักษร) | ตามที่ระบุใน FR-16 ถึง FR-18 |

## 6. หมายเหตุ
